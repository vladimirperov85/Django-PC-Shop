# Технологии

## Стек проекта

| Технология | Версия | Роль в проекте |
| ---------- | -------|--------------  |
| Python | 3.11+ | Язык разработки |
| Django | 5.2 | Веб-фреймворк: ORM, маршрутизация, шаблоны, админка, аутентификация |
| SQLite | встроенная | СУБД для локальной разработки |
| PostgreSQL | 16 | СУБД продакшена |
| Pillow | 12.2 | Обработка изображений товаров (ImageField) |
| python-decouple | 3.8 | Вынесение конфигурации и секретов в `.env` |
| Gunicorn + Nginx | — | Продакшен: WSGI-сервер и обратный прокси |
| Git + GitHub | — | Версионирование и хостинг кода |

## Почему Django

- **«Всё включено»**: аутентификация пользователей, админ-панель, защита от CSRF и SQL-инъекций работают из коробки — не пришлось собирать проект из десятка отдельных библиотек.
- **ORM** — работа с базой данных через Python-классы вместо ручного SQL. Миграции автоматически синхронизируют схему БД с моделями.
- **Зрелость и документация**: фреймворк существует с 2005 года, документация — эталонная в индустрии.

## Ключевые архитектурные решения

### Две СУБД через один код

Выбор базы данных задаётся переменой `DB_ENGINE` в `.env`:

- **SQLite** для разработки — не требует установки и настройки, база — один файл.
- **PostgreSQL** для продакшена — производительность и надёжность под нагрузкой.

Код приложения при этом не меняется: Django ORM абстрагирует различия СУБД.

### Конфигурация вне кода

`SECRET_KEY`, пароли БД и режим `DEBUG` хранятся в `.env` (python-decouple) и не попадают в git-репозиторий. Утечка репозитория не раскрывает секретов.

### Корзина на сессиях

Корзина хранится в серверной сессии (`CART_SESSION_ID`), а не в БД:

- покупатель может собирать заказ **без регистрации**;
- не создаётся «мусорных» записей в БД от неоформленных корзин;
- заказ записывается в БД только в момент оформления.

### Точность денежных расчётов

Цены — `DecimalField`, а не `FloatField`: десятичный тип исключает ошибки округления двоичной арифметики с плавающей точкой.
