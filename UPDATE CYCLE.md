# 🔄 ЦИКЛЫ ОБНОВЛЕНИЯ ПРОЕКТА PC_Shop

> Шпаргалка: какой цикл обновления запускать в зависимости от того, что мы изменили.
> Все команды выполняются на сервере (SSH), в папке `/root/PC_Shop`.

---

## Базовые шаги (строительные блоки любого цикла)

| Шаг | Команда | Что делает |
|-----|---------|-----------|
| 1. Код | `git pull origin main` | Скачать новый код с GitHub |
| 2. Зависимости | `pip install -r requirements.txt` | Установить новые пакеты (в .venv) |
| 3. Миграции | `python manage.py migrate` | Применить изменения моделей к БД |
| 4. Статика | `python manage.py collectstatic --noinput` | Пересобрать статику в staticfiles/ |
| 5. Перезапуск | `sudo systemctl restart gunicorn` | Перезапустить приложение (обновить код в памяти) |

> Шаги 2–4 выполняются в активированном виртуальном окружении:
> `cd /root/PC_Shop && source .venv/bin/activate`

---

## Какой цикл запускать в зависимости от изменений

| Что изменили | Шаги | Пояснение |
|-------------|------|-----------|
| **Только Python-код** (views, urls, логика без новых полей) | 1 + 5 | Код обновился на диске, Gunicorn перезапустился и загрузил новую версию. Миграции и статика не нужны. |
| **Новое поле/модель** (изменили models.py + создали миграцию) | 1 + 3 + 5 | Миграция приводит базу в соответствие с новой моделью. Без неё Django упадёт с ошибкой БД. |
| **CSS/JS/статические файлы** | 1 + 4 + 5 | Nginx отдаёт статику из staticfiles/. Без collectstatic браузер получит старые стили. |
| **Новый пакет** (pip install чего-то) | 1 + 2 + 5 | Сервер должен установить пакет, иначе ImportError. |
| **Полное обновление** (всё сразу) | 1 + 2 + 3 + 4 + 5 | Универсальный цикл — безопасен всегда, ничего не пропустит. |

---

## Универсальный цикл (полное обновление)

```bash
cd /root/PC_Shop
source .venv/bin/activate

git pull origin main
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
sudo systemctl restart gunicorn
```

> **Совет:** если не уверены, что именно менялось — выполняйте полный цикл. Он безопасен и ничего не пропустит.

---

## Ключевые моменты (почему так)

- **Gunicorn держит код в памяти** — без перезапуска (шаг 5) изменения Python-кода не вступят в силу.
- **Nginx отдаёт статику из staticfiles/** — без collectstatic (шаг 4) браузер получит старые CSS/JS.
- **Миграции = изменения БД** — без migrate (шаг 3) база не соответствует коду → ошибки.
- **Пакеты = новые библиотеки** — без pip install (шаг 2) код с новым импортом упадёт.
- **git pull = «мост» с GitHub** — сервер не узнает об изменениях, пока не выполнить pull.

---

## Порядок работы (главное правило)

1. Код правится **локально** (на ПК) → тестируется → `git push` на GitHub
2. На сервере выполняется `git pull` + нужные шаги из таблицы выше
3. Проверка в браузере `http://139.100.238.148`

> На сервере код **не правится**. Сервер — только «приёмник» готового кода из Git.
